# Paper Kart｜Codex 最简开发任务清单
目标：用最少步骤完成一个可在网页运行、支持头像驾驶员、AI 对手和多人联机的 3D 纸片风赛车游戏。
## 推荐技术栈
- **3D 游戏：** PlayCanvas + TypeScript
- **网页/UI：** React + Vite
- **实时联机：** Colyseus
- **账号/头像/战绩：** Supabase
- **开发方式：** Codex + GitHub
## 执行原则
**严格按 01 → 05 顺序执行。每一步完成、运行通过、提交 Git 后，再把下一步任务交给 Codex。不要让 Codex 同时做五步。**
第一版只追求：**能打开、能开车、能比赛、能上传头像、能和 AI/真人一起跑、能分享网址。** 暂时不做商城、皮肤系统、好友、赛季、语音、复杂匹配和大型地图。
---

## 01｜搭好项目，并先做出“能开的赛车”
**目标：** 先得到一个浏览器可运行的单机原型：1 张赛道、1 台赛车、键盘/触屏可控制、可以跑圈。不要先做登录、联机和复杂美术。
### 直接复制给 Codex
```text
请在当前仓库中创建 Paper Kart 的第一版可运行项目。

技术要求：
- TypeScript
- React + Vite 负责网页、菜单和 HUD
- PlayCanvas 负责 3D 游戏场景
- 游戏逻辑与 UI 分离
- 项目结构必须清晰，后续可以接 Colyseus 和 Supabase

本阶段只完成：
1. 首页有“开始游戏”按钮。
2. 创建一张简单的封闭环形 3D 赛道，包含起点、终点、检查点和 3 圈规则。
3. 创建一台卡通小赛车。
4. 实现 Arcade Kart Controller：加速、减速、左右转向、漂移、漂移蓄力小喷、越界自动重生。
5. PC 支持 WASD/方向键，手机浏览器显示虚拟方向和漂移按钮。
6. 摄像机第三人称跟随赛车。
7. HUD 显示当前圈数、名次占位、速度。
8. 使用轻量级纸片卡通风格：低模、哑光材质、手绘轮廓感、纸张质感，不追求真实车辆物理。

不要做：账号、数据库、多人联网、商城、复杂车辆改装。

完成后请自行运行项目、修复编译错误，并确保 npm run dev 可以直接启动。
```
### 完成标准
- [ ] 浏览器打开即可进入游戏。
- [ ] 赛车能完成 3 圈比赛，不会频繁穿模或翻车。
- [ ] 键盘和移动端触控至少都能控制。
- [ ] 项目代码已经为后续联机预留 game-core / client / shared 结构。
---

## 02｜一次完成头像、AI、道具和完整比赛循环
**目标：** 把单机 Demo 直接变成一局完整游戏：用户上传头像，头像成为赛车手；不足玩家由 AI 补齐；加入少量道具和结算。
### 直接复制给 Codex
```text
继续开发当前 Paper Kart 项目，把它升级成完整的单机比赛版本。不要重写已有架构。

本阶段一次性完成以下功能：

A. 玩家头像
- 游戏开始前必须允许玩家上传头像。
- 支持裁切为正方形。
- 将头像处理成“纸片贴纸”视觉：白色描边 + 轻微纸张质感。
- 把头像作为驾驶员头部贴图显示在赛车驾驶位上。
- 未上传时使用默认头像。

B. AI 赛车手
- 一局固定 6 台赛车：1 名真人 + 5 名 AI。
- 使用赛道 Racing Spline / Waypoints 驾驶。
- AI 能自动加速、转弯、漂移、走完整赛道并完成比赛。
- 做 3 档难度参数，但先只在代码中配置即可。

C. 道具系统
只实现 4 个原创纸片主题道具：
1. 纸飞机：追踪前方赛车并造成短暂减速。
2. 胶水：落在赛道上，经过会减速。
3. 纸箱护盾：短时间抵挡一次攻击。
4. 弹簧：立即向前加速冲刺。

在赛道上放置道具盒；拾取后随机获得一个道具。

D. 完整比赛
- 6 台车同时起跑。
- 显示实时排名、圈数、当前道具。
- 比赛结束显示 1~6 名排名和玩家头像。
- 提供“再来一局”和“返回首页”。

E. 纸片视觉
- 赛车、树、路牌、护栏、建筑尽量用纸板/贴纸/手绘材质表现。
- 保持低面数和网页性能。
- 不要添加重型后处理和超高分辨率贴图。

完成后进行一次完整自动检查，确保真人和 5 个 AI 都能跑完比赛。
```
### 完成标准
- [ ] 上传头像后，游戏内驾驶员能够显示该头像。
- [ ] 1 真人 + 5 AI 能完整跑完 3 圈。
- [ ] 4 个道具均可拾取和生效。
- [ ] 存在起跑、比赛、结束、再来一局的完整闭环。
---

## 03｜接入多人联机，真人不足自动用 AI 补位
**目标：** 把已经稳定的单机游戏接成 2～6 人网页对战，并保持 AI 补位。
### 直接复制给 Codex
```text
在不破坏现有单机玩法的前提下，为 Paper Kart 接入 Colyseus 多人联机。

要求：
1. 新增“创建房间”和“加入房间”功能。
2. 创建房间后生成简短房间码。
3. 支持 2~6 名真人进入同一个比赛房间。
4. 比赛开始时，如果真人不足 6 人，服务器自动用 AI 补满 6 台赛车。
5. 服务端为权威状态：负责比赛状态、圈数、检查点、道具结果、AI、最终名次。
6. 客户端只发送控制输入：加速、刹车、转向、漂移、使用道具。
7. 本地玩家使用预测/修正；其他赛车使用插值，尽量避免瞬移。
8. 支持玩家掉线后的基础清理；掉线玩家允许转换为 AI 接管。
9. 首页保留“单人比赛”入口，联网失败时仍可玩单机。
10. 添加一个简单联机大厅，显示玩家头像、昵称、Ready 状态。

请优先保证稳定，不要加入语音、聊天、观战、复杂匹配系统。
完成后至少本地同时启动两个浏览器客户端进行联机验证。
```
### 完成标准
- [ ] 两个浏览器能进入同一房间并看到彼此赛车。
- [ ] 真人不足时自动补 AI，总车辆数保持 6。
- [ ] 圈数、排名、道具和比赛结束结果由服务器统一判定。
- [ ] 网络同步没有明显持续抖动或频繁瞬移。
---

## 04｜一次接完账号、头像存储和多端同步
**目标：** 让同一玩家换电脑或手机登录后，仍能保留头像、昵称和基础战绩。
### 直接复制给 Codex
```text
为当前 Paper Kart 项目接入 Supabase，只实现游戏真正需要的最小数据系统。

需要：
1. Supabase Auth：支持邮箱登录，另外保留游客模式。
2. Supabase Storage：保存玩家头像。
3. 数据表只需要最小字段：
   - users/profile：user_id、nickname、avatar_url、created_at
   - race_stats：user_id、races、wins、best_finish、updated_at
4. 玩家登录后自动读取昵称、头像和战绩。
5. 上传新头像后自动更新 Storage 和 profile。
6. 比赛结束后只记录必要战绩。
7. 在 PC 和手机浏览器登录同一账号时可以读取同一份资料。
8. 把 Supabase URL / key 放入环境变量，并提供 .env.example。
9. 处理游客模式：游客也必须能正常玩单机和加入联机房间，只是不做永久战绩同步。

不要做好友系统、商城、赛季、成就、支付和复杂后台。
```
### 完成标准
- [ ] 用户能注册/登录，也能直接游客游玩。
- [ ] 头像上传后刷新页面仍然存在。
- [ ] 同一账号换设备登录可以恢复昵称、头像和基础战绩。
- [ ] 敏感配置没有硬编码进仓库。
---

## 05｜上线可玩的网页版，并只做必要优化
**目标：** 不继续堆功能，直接把游戏做成一个可以分享链接体验的成品。
### 直接复制给 Codex
```text
请对 Paper Kart 做上线前最后整理，并部署成可公开访问的网页版本。

只完成必要事项：
1. 修复现有 TypeScript、构建、运行时错误。
2. 优化首屏加载：压缩模型、纹理、音效，使用合理懒加载。
3. PC 和移动端自适应。
4. 添加加载页、断线提示、重新连接、返回大厅。
5. 添加基础音效：引擎、漂移、碰撞、道具、倒计时、冲线；背景音乐可选且默认音量较低。
6. 首页流程整理为：
   上传/选择头像 → 昵称 → 单人比赛 / 创建房间 / 加入房间。
7. 做一次完整回归：单机、AI、头像、道具、联机、Supabase 登录、移动端。
8. 前端部署到 Vercel 或 Cloudflare Pages；Colyseus 服务端部署到可长期运行的 Node 环境。
9. 输出 README：本地启动、环境变量、部署方式、主要目录说明。
10. 不再增加新玩法，优先解决 bug、性能、易用性。

最终目标：任何人拿到网址后，不需要安装客户端，就能上传自己的头像并开始纸片赛车比赛。
```
### 完成标准
- [ ] 有一个公网网址可以直接打开游戏。
- [ ] PC 与主流手机浏览器均可以完成一局比赛。
- [ ] 多人房间可以创建、加入并完成比赛。
- [ ] README 足够让后续 Codex 继续维护项目。
